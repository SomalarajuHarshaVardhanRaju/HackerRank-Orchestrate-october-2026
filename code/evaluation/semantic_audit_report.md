# Read-only semantic evidence audit: COMPLETE cases

**Audit scope:** the 122 rows marked `COMPLETE` in the existing root `output.csv`; output was read only. Evidence was evaluated against identity aliases from current identity and audit-history data. A resource was considered explicitly linked only when the same parsed source record (or correlated log trace) contained the subject identity and resource. Timestamp proximity, inferred target resources, workflow statuses, and unlinked activity results were not accepted as subject-resource proof.

**Result:** PASS 0; FAIL 115; NEEDS_REVIEW 7. The audit found 376 cited verification steps: 186 with explicit subject/resource linkage and 177 with direct evidence also matching the claimed state. All cited references were checked against each request/audit window; cutoff-pass cases: 122/122. Directly evidenced core profile/tombstone proof: 30/122.

**Classification:** FAIL means at least one cited state is not directly established, the required core state is missing/unproven, the citation is outside the cutoff, or linked evidence contradicts a policy-required treatment. NEEDS_REVIEW means no direct contradiction was found by the checks but complete policy coverage cannot be established. PASS requires all evidence and policy obligations to be demonstrated; absence of contrary evidence is not enough.

**Policy limit:** `deletion_rules.csv` requires evaluating each relevant copy and conditional records. The cited verification set alone does not prove the global record inventory or all active synchronization/import/restore paths. For support records, shared-context/ownership conditions and legal-hold applicability require source-specific review. Thus an otherwise consistent case can remain NEEDS_REVIEW. Rules checked include rule_01 through rule_15 as applicable. In 25 cases, directly subject-linked evidence also showed a record state inconsistent with its required treatment; those case IDs and evidence references are called out in their rows.
